`security-runtime-candidate-20261016` is a separate opt-in profile with exact actual merged CP, executor, Manifest, Replay, ODES and Evidence Pack revisions. Existing profiles remain unchanged. Loaded source identities and tracked source bytes are checked before using the executor; source identity is not independent institutional trust. Since F5b each expected module's file is located without importing it, its Git HEAD, tracked status and tracked membership are checked, and only then is it imported and required to load from that verified file. This in-process Git check is a provenance-consistency check, not a trust boundary: it runs inside the process it describes and cannot defend against an environment that is already compromised. The gate against modified, untracked or shadowed dependency checkouts is the qualification harness's fresh-checkout pre-check.

The profile is never obtained from an incoming message. The existing Control Plane validates and freezes this configuration; synthetic fixtures must additionally opt into `allow_test_time`. No default execution profile is activated or institution adopted by this API change.

The reference retains actual runtime-authority journals, typed refusals, original effect ownership, acknowledgements, unknown outcomes and derivative recovery evidence through the strict migrated consumers. A retained failure-record identifier is not proof of its row's independent durability. Historical records require their original revision-pinned recovery path; the new profile does not relabel old evidence.
