# Repaired runtime Exchange profile — 16 October 2026

`security-runtime-candidate-20261016` is a separate opt-in profile with exact actual merged CP, executor, Manifest, Replay, ODES and Evidence Pack revisions. Existing profiles remain unchanged. Loaded source identities and tracked source bytes are checked before using the executor; source identity is not independent institutional trust. Since F5b each level of each expected module is resolved with the import system's own finders (`find_spec` for the top-level package, `PathFinder.find_spec` per sub-level), which run no module code and return the origin the import will actually use. Only plain source files are accepted, so a package directory, extension module or sourceless bytecode shadowing the tracked `.py` is refused. Every origin in the chain must be tracked at the pinned HEAD with no tracked changes, and the package tree must contain no untracked or ignored files (including `__pycache__` bytecode). Every directory of a candidate checkout that is on `sys.path` (for example `src/` or the checkout root) must contain no untracked or ignored importable top-level entry (`*.py`, `*.pyc`, extension modules, package or namespace directories) that could shadow a module the tracked code imports; ignored non-importable entries such as `*.egg-info` or `.venv` are allowed. Candidate profiles therefore require `PYTHONDONTWRITEBYTECODE=1` and checkouts without `__pycache__`; normal bytecode caches are refused with a message naming the file. Nothing from a candidate package is imported until all chains are verified; each chain is re-resolved immediately before import, and the imported `__file__` must equal the verified file. This in-process Git check is a provenance-consistency check, not a trust boundary: it runs inside the process it describes and cannot defend against an environment that is already compromised. The gate against modified, untracked or shadowed dependency checkouts is the qualification harness's fresh-checkout pre-check.

The trusted Python caller must supply `runtime_authority_profile` to `run_exchange` and `resume_original_exchange`. Missing configuration fails before opening the exchange store. The profile is never obtained from an incoming message. The existing Control Plane validates and freezes this configuration; synthetic fixtures must additionally opt into `allow_test_time`. No default execution profile is activated or institution adopted by this API change.

The reference retains actual runtime-authority journals, typed refusals, original effect ownership, acknowledgements, unknown outcomes and derivative recovery evidence through the strict migrated consumers. A retained failure-record identifier is not proof of its row's independent durability. Historical records require their original revision-pinned recovery path; the new profile does not relabel old evidence.

Scenario tests and results are maintained in the central qualification repository, `suites/security-runtime`. No selected lock/profile, production action or publication acceptance changes.
